# Sim 测试用例

`test/cases/*.sim` 每个文件即一个用例，单文件同时承载「代码 + 期望输出」：

```sim
// <action> [key=value ...]
// 期望输出的第 1 行
// 期望输出的第 2 行
//
<Sim 代码>
```

- **首行**：动作 + 标志。动作 `lex` / `parse` / `analyze`（`compile` / `run` 见
  `docs/plans.md` P1，尚未支持）。
- **期望块**：首行之下连续的 `//` 行（每行剥掉一个 `//` 与一个可选空格；
  `//` 单独一行表示空行）。空块 = 期望无输出。块以第一个非注释行结束。
- **代码**：注释块之下。注释对编译器不可见，**用例文件本身即合法 Sim 源码**——
  runner 直接以该文件为输入，因此诊断位置就是文件中的真实行号。
- **比对**：实际输出与期望块经归一化（去 ANSI 颜色、CRLF→LF、去尾部换行）后**全文等值**。

各动作的输出：

| action | 输出 |
|---|---|
| `lex` | token 流（`行:列` + kind + 原文，每个 token 一行）；只对代码块做词法，位置相对代码块从 1 计 |
| `parse` | 解析成功 = AST 打印；有诊断 = 诊断渲染全文 |
| `analyze` | 分析成功 = HIR 打印；有诊断 = 诊断渲染全文 |

标志：

- `known-bug=<ID>`：已知缺陷的**行为快照**（ID 对应 `docs/known-issues.md` 的条目）。
  缺陷修复或恶化都会使期望不匹配而测试失败，提示同步文档；修好后移除标志、把用例转正。
  runner 会校验文档中确实存在该条目。
- `skip=<原因>`：跳过（原因不含空格，用短标识）。

运行：

- 全部：`go test ./test/...`（用例并行执行；lex/parse/analyze 不需要 LLVM）
- 单个：`go test ./test -run 'TestCases/analyze_f23' -v`
- 重写期望：`go test ./test/... -update`（自迭代至稳定；随后务必 `git diff` 审查内容）

约定：

- 期望块中诊断路径相对于运行目录（`go test` 下即 `test/`），如 `cases/xx.sim:3:16`。
- 新增 known-issues 条目时应同步新增 `known-bug=<ID>` 用例；条目修复删除时用例转正。
